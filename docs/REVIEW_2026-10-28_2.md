# Повторная рецензия ЦБВакансии 1.2.3 (9)

Дата: 28.10.2026. Объект: ветка `codex/independent-vacancy-sources`, коммит `e9b04b8`. Это 11 коммитов поверх `26105b8`, предмета первой рецензии. Добавлены источник trudvsem.ru, реестр организаций, общий планировщик обновлений и выгрузка всех вакансий в PDF. Избранное удалено.

Правило проверки по заданию владельца: по пунктам, которые исправлены (в том числе иначе, чем предлагалось), проверялась только техническая корректность исправления, без повторного функционального разбора. Решения владельца, зафиксированные в `docs/REVIEW_RESPONSE_2026-10-28.md` (бессрочный архив, публикация только полного сбора), не оспариваются. Отмечены только технические последствия этих решений.

Метод: чтение всего нового и измененного Swift-кода, тестов, CI и скриптов. На Linux прогнаны Python-тесты и `verify_independence.py`. Сборка тестового стенда проверена по списку файлов. Swift toolchain в среде аудита нет, выводы по Swift получены из кода. Реквизиты НСИС, УК ФКБС и РНПК в `OrganizationRegistry.swift` сверены с ЕГРЮЛ через открытые агрегаторы и совпадают.

## Итог

Работа над первой рецензией сделана добросовестно: вынесена запись архива из сетевого шлюза hh.ru, PDF больше не блокируется пропавшим наблюдением, исправлены округление дат, двойное декодирование сущностей, залипание классификации, CI получил `permissions` и строгую конкурентность во всех конфигурациях.

Главные проблемы новой версии:

1. Ответ на рецензию содержит неверное утверждение: HTML-импорт через WebKit на главном потоке не заменен (P1-13 по-прежнему открыт).
2. Исправление P0-2 сделано только для hh.ru. В клиенте trudvsem.ru сбой записи архива по-прежнему срывает запрос.
3. Конфигурация работодателей trudvsem.ru жестко падает при любом изменении реестра в новой версии приложения. Ближайшее обновление с новой организацией сломает вкладку trudvsem.ru у всех существующих пользователей.
4. Экспорт карточки и статистики в файл, выбранный в диалоге с подтверждением замены, завершится ошибкой песочницы.
5. Массовая выгрузка в PDF падает целиком на первой недоступной вакансии и имеет квадратичную стоимость подготовки.
6. Стенд надежности `scripts/benchmarks/build.sh`, на который ссылается ответ на рецензию, не собирается.

## Новые и оставшиеся дефекты

### P0

**Н-1. trudvsem.ru: сбой записи архива срывает запрос.** `TrudvsemAPIClient.swift:95`: `page.observationID = try evidence.capture(...)` стоит внутри `do`, ошибка не перехватывается. Переполненный диск, отказ прав или любая ошибка записи превращает успешную страницу в ошибку. Организация попадает в `issues`, сбор становится неполным, и по политике публикации новая выборка не появится никогда, пока диск не освободят. Исправление: тот же прием, что в `HHAPIClient.data(for:)` – `do/catch`, `NSLog` и `observationID = nil`.

**Н-2. HTML-импорт через WebKit не заменен.** `VacanciesPDFExporter.swift:841–860`: `VacancyHTMLAttributedText.convert` по-прежнему вызывает `NSMutableAttributedString(data:options: [.documentType: .html])`. Его использует `importedDescription(for:)` (`:253–255`), а тот – `PDFVacancySnapshot.init` (`:1084`) для каждой вакансии hh.ru при экспорте. В `REVIEW_RESPONSE_2026-10-28.md` сказано: «текущий конвертер PDF уже использует собственный ограниченный HTML parser вместо системного HTML importer». Это не соответствует коду. Теперь массовая выгрузка проходит по всем отображаемым вакансиям, а не по избранному, и подвисание главного потока с вложенным циклом событий растет пропорционально выборке. Исправление: собственный конвертер узкого подмножества тегов, которое уже оставляет `sanitize`, и исправление ответа на рецензию.

**Н-3. Обновление реестра ломает вкладку trudvsem.ru.** `OrganizationRegistry.swift:71–89`: `TrudvsemEmployerConfigurationStore.loadOrCreate` требует, чтобы в файле `employers-trudvsem.json` была запись для каждой организации реестра с точно совпадающими ИНН и ОГРН. Иначе ошибка «Реквизиты ... в конфигурации». Файл создается один раз и не дополняется. Сценарий: версия с новой организацией в `OrganizationRegistry.all` (так уже были добавлены НСИС и УК ФКБС) у пользователя, у которого файл создан предыдущей версией. `TrudvsemViewModel.load()` (`:96`) получает ошибку в общем блоке `do` и не загружает даже сохраненный снимок. `refresh()` (`:115`) падает до сбора. Вкладка неработоспособна до ручного удаления файла в контейнере. Исправление: слияние по образцу `EmployerConfigurationStore` – добавлять недостающие организации, расходящиеся реквизиты брать из встроенного реестра, при этом сбрасывать `confirmedCompanyCodes`. Загрузку снимка отделить от загрузки конфигурации.

**Н-4. Экспорт в файл, выбранный с заменой, падает в песочнице.** `PDFExportWorker.exportPersonal`, `exportStatistics`, `exportDocument` теперь пишут через `PDFNewFileWriter.write(..., in: destination.deletingLastPathComponent())`, то есть `open(O_CREAT | O_EXCL)`. Если пользователь в `NSSavePanel` выбрал существующий файл и подтвердил «Заменить», `open` вернет `EEXIST`, и запись перейдет к имени `..._2.pdf` в том же каталоге. App Sandbox дает доступ только к выбранному в панели URL (`com.apple.security.files.user-selected.read-write`), а не к его каталогу, поэтому создание другого имени будет запрещено, и пользователь получит ошибку вместо замены (поведение на устройстве требует проверки, механизм песочницы известный). Без замены файл молча получает другое имя, чем выбрано в диалоге. Исправление: для одиночного файла из `NSSavePanel` писать атомарно в выбранный URL (`Data.write(options: .atomic)`), режим `O_EXCL` оставить для выгрузки в каталог.

**Н-5. Массовая выгрузка hh.ru падает целиком на одной вакансии.** `VacancySearchViewModel.preparedForPDF`: прежний запасной вариант с `exportDataNotice` удален, любая ошибка `sharedDetails` пробрасывается. `exportVacanciesPDF` дозагружает детали для каждой отображаемой вакансии. Одна вакансия, снятая с hh.ru за время между обновлением и экспортом (404), обрывает экспорт тысячи вакансий после десятков минут ожидания (запросы идут с интервалом 1 секунда). Исправление: 404 и сетевые ошибки по одной вакансии – локальные данные карточки с пометкой в PDF. Прерывать выгрузку только на ограничениях доступа (401, 403, 429, CAPTCHA), как было.

**Н-6. Публикация hh.ru может быть заблокирована навсегда.** Решение «публиковать только полный сбор» не оспаривается, но в коде есть детерминированные источники неполноты, которые сработают при каждом обновлении:

- `VacancyCollectionService.swift`, дополнительный поиск полевых учреждений: при `pages > 2` всегда добавляется issue «Дополнительный поиск ограничен 200 кандидатами»;
- `collectByDictionaryDimension`: если и словари не сужают раздел до 2 000, читаются доступные 2 000, а недостача всегда остается issue.

Если одно из условий выполняется устойчиво, новая выборка не публикуется никогда, а у нового пользователя без снимка экран останется пустым. Ветка «Готово с пропусками» в `performSearch` после `guard` стала недостижимой. Исправление: разделить issue на «временные» (ошибки, ограничения) и «структурные» (лимит API), структурные не блокируют публикацию, но показываются. Удалить недостижимую ветку.

### P1

**Н-7. Квадратичная подготовка массового PDF.** `PDFExportWorker.prepare`: для каждой вакансии вызывается `headerPageCount(context(current.contexts + [vacancy.context]))`. Ключ кеша `HeaderKey` включает полный список `observationIDs`, который растет с каждой вакансией, поэтому кеш почти всегда промахивается. Каждый промах – полная разметка заголовка с блоком `sourceEvidence`, где по полю на каждое наблюдение. Для N вакансий это O(N²) разметок. Исправление: оценивать заголовок по числу наблюдений с запасом и проверять точно только при закрытии части.

**Н-8. Числа в статистике trudvsem.ru выводятся как `Double`.** `TrudvsemPDFFormatter.swift:58, 80`: `String(places.reduce(0, +))` и `"\(min) — \(max)"` для `Double` дают «12.0» и «50000.0 — 120000.0». Исправление: форматировать через `NumberFormatter` с разделителем тысяч, без дробной части.

**Н-9. Запись конфигурации при чтении.** `EmployerConfigurationStore.loadOrCreate` при любой разнице с миграцией пишет файл. Сбой записи бросает ошибку из чтения, и список работодателей hh.ru не загружается, хотя прочитан. Даты проверки `"2026-10-22" : "2026-10-16"` и идентификатор `"9942121"` зашиты дважды (`EmployerConfiguration.swift`, инициализатор и миграция). Исправление: вернуть прочитанное с предупреждением при сбое записи, даты держать в `OrganizationRegistry`.

**Н-10. Главный поток при запуске.** `TrudvsemViewModel.load()` синхронно читает и декодирует `vacancies-trudvsem.json` с полными исходными записями (`SourceJSONValue`) на главном акторе, `refresh()` так же синхронно кодирует и пишет снимок (`store.save`). У hh.ru снимок читается в фоне, но `snapshot.results` вычисляется на главном акторе и заново классифицирует каждую вакансию с сохраненным описанием. Исправление: `Task.detached` для чтения, записи и построения результатов.

**Н-11. Полнотекстовый поиск пересчитывает HTML на каждом изменении фильтра.** `TrudvsemViewModel.displayedResults` вызывает `TrudvsemDescriptionFormatter.searchableText`, то есть сборку HTML и `readableHTMLText` с десятком регулярных выражений для каждой вакансии при каждом сбросе кеша. В hh.ru то же через `plainTextDescription`. Исправление: вычислять текст для поиска один раз при получении данных.

**Н-12. Регулярные выражения классификатора компилируются заново.** `FieldInstitutionClassifier.matches` использует `String.range(of:options: .regularExpression)` – компиляция на каждом вызове, до 25 выражений на предложение. Теперь классификатор работает и для каждой вакансии trudvsem.ru. Исправление: статические `NSRegularExpression`.

**Н-13. Кеш отображаемого списка hh.ru не сбрасывается при смене работодателей.** `displayedCache` зависит от `organizationKey(forHH:)`, а тот – от `configuredEmployers`. При перечитывании конфигурации в `performSearch` кеш не сбрасывается. Там же `employerFilterOptions`: проверка `titlesByID[id] == nil` идет по идентификатору hh.ru, а запись – по ключу организации, поэтому проверка никогда не срабатывает. Исправление: `didSet` у `configuredEmployers` и проверка по тому же ключу.

**Н-14. Гонка отложенной записи снимка.** `apply(details:)`: `snapshotSaveTask?.cancel()` отменяет только ожидание, но не уже запущенный `Task.detached { save }`. Две записи могут завершиться в обратном порядке. Отложенная запись не сравнивает `resultsRevision`, и снимок старых результатов, запущенный во время обновления, способен перезаписать свежий снимок после него. Исправление: сериализовать записи в одном акторе с номером ревизии и отменять отложенную запись при публикации нового сбора.

**Н-15. Вложенные префиксы в сообщении о неполном сборе trudvsem.ru.** `TrudvsemViewModel.refresh` оборачивает список issue в `TrudvsemError.incomplete`, а каждое issue уже содержит `localizedDescription` того же типа. Пользователь видит «Неполный сбор trudvsem.ru: Банк России: Неполный сбор trudvsem.ru: ... Предыдущая выборка сохранена.. Предыдущая выборка сохранена.». Там же метрики нового неполного сбора показываются рядом со старой выборкой. Исправление: отдельный тип для issue без повторного префикса, метрики обновлять только при публикации.

### P2

**Н-16. Типографика строк.** Длинное тире «—» в пользовательских строках: `OrganizationRegistry.swift:25–26` (поле `relationship`), `TrudvsemPDFFormatter.swift:60, 80, 81`, `VacanciesPDFExporter.swift:600`, а `readableHTMLText` превращает `&mdash;` в «—». Буква ё в строках по-прежнему используется в одних местах и отсутствует в других. Выбрать правило и прогнать по всем файлам.

**Н-17. Мертвый код.**

- `performSearch`: присваивание `summary.fieldInstitutionEvidence = priorEvidence[...]` больше ни на что не влияет – конструктор классифицирует заново.
- `CollectionRunClient.pagesByEmployer` записывается и нигде не читается.
- `TrudvsemEmployerConfiguration.confirmedCompanyCodes` записывается при каждом обновлении и нигде не читается.

**Н-18. Мелочи в клиенте trudvsem.ru.**

- `Retry-After: inf` или `1e400` дает бесконечный `cooldownUntil`, и `TrudvsemRequestGate` отклоняет все запросы до перезапуска приложения. Комментарий это объявляет намеренным, но значение стоит ограничить сверху.
- Параметр `offset` передается как номер страницы. По открытым примерам API это номер страницы, но начало отсчета (0 или 1) требует проверки по документации trudvsem.ru: при отсчете с 1 первая страница будет прочитана дважды и сработает защита «Повторяющаяся страница».
- `SourceJSONValue.text` для числа выводит `%.0f`: ИНН или код, переданный числом, теряет ведущий ноль. Для текущих ИНН не критично.
- `TrudvsemVacancy.organization` и `createdDate` при каждом обращении делают линейный поиск по реестру и создают три форматтера даты.

**Н-19. Версии в документации расходятся.** `project.pbxproj`: 1.2.3 (9). README: имя DMG `HHVacancyCBR_1.2_6_...`. `docs/VALIDATION.md`: 1.2 (6). Коммит `c99be04`: 1.2.1 build 7. Записей о 1.2.1–1.2.3 нет. `User-Agent` содержит запасное значение `"1.2.1"`.

**Н-20. Интерфейс trudvsem.ru против hh.ru.** У карточек trudvsem.ru нет идентификаторов доступности для кнопок, нет отметки «Скопировано», раскрытая карточка не сворачивается, когда фильтр ее скрывает. Описание собирается из полей в `<p>` без переносов строк. Переключение источника через `if/else` в `ContentView` уничтожает неактивное дерево: теряется позиция прокрутки, описание в WebView загружается заново.
