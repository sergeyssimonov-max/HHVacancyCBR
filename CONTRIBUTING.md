# Участие в разработке

Начните с [разработки](docs/DEVELOPMENT.md), [архитектуры](docs/ARCHITECTURE.md) и [проверок](docs/TESTING.md). Для собственного продукта — [инструкция форка](docs/FORKING.md).

Соблюдайте действующий AGENTS.md. В этом репозитории работа идёт в main; отдельная ветка требует запроса владельца. Не переписывайте историю, не включайте постороннюю незавершённую работу и не меняйте пользовательские данные ради тестирования.

Описывайте конкретную проблему и итоговое поведение. Разделяйте рефакторинг и функциональные изменения. Сначала воспроизведите риск проверкой на исходной реализации, затем меняйте код небольшими проверяемыми этапами. Не ослабляйте assertions и не обновляйте эталоны ради зелёного результата. При переносах сохраняйте полные имена XCTest-селекторов или объясняйте их изменение и адаптируйте выборочные команды.

Перед передачей выполните обязательные проверки из TESTING.md, приведите фактические результаты и ограничения. Документация должна ссылаться на реальные символы и команды. Для PDF нужны содержимое, вложения и визуальная проверка; для интерфейса — сценарии и снимки. Значимое ухудшение повторных performance-замеров требует объяснения.

Не печатайте значение встроенного токена. Разрешённая модель его использования описана в README; документационные изменения не меняют авторизацию. Не меняйте лицензию, видимость репозитория, release или Git history без отдельного решения владельца. Основной проект пока не содержит собственной лицензии: условия распространения кода должен определить владелец. Уведомления Streebog сохраняются.

Порядок релиза — [RELEASING.md](docs/RELEASING.md). Подготовка документации не подразумевает новую установку приложения: фиксируйте commit происхождения каждого DMG отдельно от последующих коммитов отчётов.
